# PolygonTown 읍내 경관 배치 기준

## 팩의 특징

`PolygonTown`은 저층 주택, 작은 상점, 정원, 정류장과 생활 소품으로 읍내의 일상적인 밀도를 만든다. 평창읍은 대도시 Skyline보다 작은 블록과 골목, 건물 출입구와 보행 흐름이 먼저 읽혀야 한다.

- 주택과 상점은 작은 블록으로 묶고 건물 사이에 숨 쉴 공간을 둔다.
- 정원·담장·수목은 법정동 경계가 아니라 생활 공간의 가장자리를 나타낸다.
- 정류장·벤치·표지는 보행 경로와 도로가 만나는 지점에 둔다.
- 배달 차량과 생활 소품은 상호작용 지점을 가리지 않는 정도로 제한한다.

## 배치 순서

1. 저층 주택과 상점으로 2~4개의 큰 생활 덩어리를 정한다.
2. 도로·골목·보행 연결 지점으로 블록 사이 이동을 연결한다.
3. 정원·담장·정류장으로 건물의 앞뒤와 공공 공간을 구분한다.
4. 배달·주차·생활 서비스 공간을 도로 접근부에 둔다.
5. 벤치·표지·작은 소품은 Task 거리에서만 보강한다.

`A`, `B`, `C`는 같은 읍내 의미의 결정적 시각 변형이며 실제 건물 주소나 상호를 뜻하지 않는다.

## LOD와 성능

- Overview는 지붕과 저층 건물 덩어리만 유지한다.
- Region은 주택·상점·정류장 조합을 블록 단위로 표시한다.
- Task는 담장·벤치·표지·배달 소품을 추가한다.
- 작은 생활 소품보다 출입구와 골목의 빈 공간을 우선한다.

## Simulation과 상호작용

- 공개 사업장 상호는 검증된 건물 관계와 근접 상호작용이 있을 때 별도 상세 조회로 표시한다.
- 정적 상점 Prefab은 실제 영업, 주문 또는 배달 완료를 뜻하지 않는다.
- 건물 출입구와 보행·차량·화물 Socket의 접근성을 검증한다.

## 금지 요소

- Town 팩만으로 실제 건물 용도·층수·상호를 확정하지 않는다.
- 주택을 반복 간격으로 줄 세우거나 담장으로 지역 전체를 둘러싸지 않는다.
- 건물과 차량으로 보행로, 정류장과 출입구를 막지 않는다.
- City 대형 건물을 근거 없이 읍내 주역으로 사용하지 않는다.

## 검토 체크리스트

- [ ] 작은 생활 블록, 골목, 공공 연결 지점의 순서가 읽힌다.
- [ ] 주택·상점·정류장·배달 공간의 출입구가 확보됐다.
- [ ] City 요소가 대도시 Skyline을 만들지 않는다.
- [ ] 전체 Footprint가 로컬 제작 경계 안에 있다.
- [ ] 실제 사업장 정보와 장식 Prefab의 의미가 분리돼 있다.
