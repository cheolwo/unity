# 평창 Farm·Hub·Town 정적 경관 배치 기획서

## 경관 목표

공공 공간자료와 Simulation 역할을 근거로 대관령 Farm, 진부 Hub, 평창 Town이 하나의 이동 가능한 로우폴리 경관으로 읽히게 한다. 실제 관측 위치와 Scenario 표현을 구분하고, Synty 자산은 표현 전용으로 사용한다.

## 영역별 구성

| 컨테이너 | 주역 | 전환과 세부 표현 |
| --- | --- | --- |
| 대관령 남서 L2 | 농장 마당과 온실 | 울타리·일반 수목으로 밭과 생활 공간을 연결 |
| 대관령 남동 L2 | 밭고랑과 경작 블록 | 반복 간격을 깨고 작업 경로를 남김 |
| 대관령 북서 L2 | 활엽·침엽 산림 전이 | 큰 군집 뒤 가장자리 개별 수목 배치 |
| 대관령 북동 L2 | 혼효림·능선·저수지 경관 | 물 근거가 없는 수계 오브젝트는 사용하지 않음 |
| Farm–Hub 회랑 | 농로와 수목대 | 출발 농촌 경관에서 물류 진입부로 점진 전환 |
| 진부 Hub | 물류 거점과 완충 수목 | 차량 회차·화물 대기 공간의 시야를 확보 |
| Hub–Town 회랑 | 물류에서 생활권으로 전환 | 콘크리트·주황에서 크림·벽돌 계열로 밀도를 낮춤 |
| 평창 Town | 주거·상업 경관 | 주택·상점·생활 소품으로 도착 생활권을 표현 |

`L4_L7_Synty경관_PresentationOnly`은 위 8개 배치 대상을 묶는 부모이며 자체 배치를 갖지 않는다.

Farm·Hub·Town 대표 구획은 각각 독립된 로컬 저작 좌표를 사용한다. 계획에 기록된 컨테이너 변환 계약이 이를 세계 Anchor로 옮기며, 이 좌표 변환은 공공 공간자료나 Simulation 권위를 변경하지 않는다.

## 네 팩 배치 기준

| 팩 | 주 역할 | 이번 대표 구획 |
| --- | --- | --- |
| [PolygonNature](../공통/PolygonNature숲경관배치기준.md) | 산림·능선·경작지 가장자리 | 대관령 산림 전이와 세 영역의 완충 수목 |
| [PolygonFarm](../공통/PolygonFarm농촌경관배치기준.md) | 경작 블록·농장 마당·집하 작업 | 대관령 Farm 대표 구획 |
| [PolygonTown](../공통/PolygonTown읍내경관배치기준.md) | 저층 주택·상점·정류장·생활권 | 평창 Town 대표 구획 |
| [PolygonCity](../공통/PolygonCity도시물류경관배치기준.md) | Station·상하차·회차·안전 설비 | 진부 Hub 대표 구획 |

네 기준 문서의 개정·개별 hash·묶음 hash와 구성 대장 개정은 함께 승인 입력으로 고정한다. 팩 이름이나 원본 Prefab 이름을 배치 계약으로 사용하지 않고, `CompositionKey`가 의미를 맡는다.

## PolygonNature 숲 경관 적용

[공통 숲 경관 배치 기준](../공통/PolygonNature숲경관배치기준.md)의 개정과 hash를 이 기획서의 승인 입력으로 사용한다.

| 배치 대상 | PolygonNature 역할 | 배치 원칙 |
| --- | --- | --- |
| 대관령 남서 L2 | 농장 마당 완충 수목 | 건물과 작업로 시야를 남기고 드문 개별 수목만 사용 |
| 대관령 남동 L2 | 경작지 가장자리 | 낮은 숲 가장자리와 개별 수목으로 밭 블록을 구분 |
| 대관령 북서 L2 | 핵심 산림 전이 | 활엽·침엽·혼효림 군집 뒤 산 능선을 두고 가장자리를 하층 식생으로 마감 |
| 대관령 북동 L2 | Farm 출발 전이 | 농로를 가리지 않는 성긴 수목대와 원경 능선 사용 |
| Farm–Hub 회랑 | 농촌 완충 수목 | 출발 40%는 수목 비중을 유지하고 Hub 접근부로 갈수록 밀도를 낮춤 |
| 진부 Hub | 외곽 완충 수목 | 회차·적재·대기 공간의 시야와 차량 동선을 침범하지 않음 |
| Hub–Town 회랑 | 생활권 전환 수목 | 산림 군집 대신 작은 수목대와 관목으로 도시 밀도 변화를 연결 |
| 평창 Town | 생활 경관 수목 | 주택·상점의 출입구를 가리지 않는 개별 수목과 작은 녹지만 사용 |

현재 실제 수계 마스크가 연결되지 않았으므로 `수변 완충지`와 `개울 회랑`은 배치하지 않는다. `산 능선`은 DEM을 대체하지 않고 Overview 원경 실루엣만 보강한다. A/B/C는 결정적 시각 변형일 뿐 현실 수종·밀도·상태 등급이 아니다.

`바위 절개지`는 최소 15도 물리 경사를 요구하지만 현재 Scenario 지형은 그 근거를 충족하지 않으므로 이번 계획에서 보류한다. 실제 `PhysicalElevation` 연결 뒤 적합 후보가 확인될 때만 다시 배치한다.

## 조명과 명암

- 첫 기준은 PC·봄·평화 상태의 `맑은 늦은 오전`이다.
- 하나의 태양을 Pitch 42도, Yaw -32도, 강도 1.30으로 사용하고 Farm·Hub·Town이 같은 시간대를 공유한다.
- PC 그림자 거리는 80m, 2048 해상도, 네 단계 Cascade `0.10 / 0.28 / 0.58`로 통일한다.
- 수관과 큰 바위는 그림자를 만들고 받으며, 하층 식생은 받기만 하고 원경 능선과 FX는 동적 그림자를 만들지 않는다.
- Linear 안개는 75~230m에서 원경을 정리하고, Neutral Tonemapping·약한 SSAO·Bloom·Vignette로 나뭇잎의 검은 뭉침과 과한 노란색을 피한다.
- 조명 Profile의 식별자·개정·hash는 배치 승인 입력이다. 값이 바뀌면 기존 Scene 적용 승인은 오래된 상태가 된다.

## 필수 요소

- 큰 지형 덩어리, 중간 군집, 작은 디테일 순서로 구성한다.
- `VisualKey`·`CompositionKey`와 결정적 hash로 같은 입력을 재현한다.
- 구획별 로컬 저작 좌표와 세계 Anchor 변환을 계획에 함께 저장한다.
- 정적 경관과 계절 사건·NPC·차량·UI 표현을 분리한다.
- Farm·Hub·Town은 같은 태양과 시간대를 공유하되 색조와 밀도로 역할을 구분한다.

## 금지 요소

- Synty 원본 Prefab 경로·GUID를 업무·공간 계약에 저장하지 않는다.
- 수계·과도한 경사·대상 컨테이너 밖에 임의 배치하지 않는다.
- `ScenarioPreview` 위치와 높이를 실제 관측 공간 사실로 표시하지 않는다.
- 정적 장식의 존재나 애니메이션을 생산·입고·운송 완료로 해석하지 않는다.

## 성능과 LOD

- Triangle·Material Slot·Draw Call·Shadow Caster·Collider·Animator 예산을 함께 검증한다.
- Overview에서는 군집과 실루엣, Region에서는 경관 블록, Task에서는 세부 자산을 우선한다.
- 예산 80% 접근 경고는 Scene 적용 승인 전에 검토한다.

## 자료 한계

- 실제 DEM Mesh와 세분류 토지피복 위치는 아직 연결되지 않았다.
- 현재 높이는 `ScenarioPreview`이며 `PhysicalElevation` 근거가 아니다.
- 공식 도로 공간자료가 없는 두 회랑은 `ScenarioRoute` 표현이다.
