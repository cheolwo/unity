# 한반도 곡면 타일 화면 오차 비교

현재 1·4·16개로 선생성되는 한반도 곡면 Mesh를 그대로 두고, 의미 자료층과
공간 상세도 선택을 분리하여 `표본 간격 기반 SSE 추정` 4/8/16px를 비교했다.
이 기록은 적정 타일 수를 확정하거나 정식 지리 quadtree·streaming을 검증한
증거가 아니다.

## 고정 조건

- Scene: `SimulationWorldShell`
- 실행: Unity Editor Play Mode
- 카메라: `세계 지구본 관찰 카메라`
- 중심: 한반도 영웅 구도, 위도 38.5도 기준
- 카메라 중심 거리: 33 Unity unit
- 지구 반지름: 18 Unity unit
- 수직 FOV: 38도
- 선택 계산 viewport 높이: 1080px
- 비교 캡처: 1920×1080, 같은 카메라·구도
- 의미 단계: 세 비교 모두 `Hubs`; 하천·거점 의미 자료층은 상세도와 독립

## 성능 해석 경계

Pipeline의 `get_performance_stats` 단일 snapshot은 각각 CPU 약
8.39/8.10/8.92ms, GPU 약 1.07/1.17/1.38ms를 반환했다. 그러나 이는 평균·p95가
아니고 전체 Editor 프레임이며 캡처 카메라에 직접 결속됐다는 보장도 없다.
따라서 이번 기록으로 60fps 성능을 확정하지 않는다.

현재 21개 Mesh는 초기화 때 모두 생성되고 활성 root만 바뀐다. 이번 비교에서
신뢰할 수 있는 직접 차이는 활성 타일·정점·삼각형 수이며, 메모리 절감·요청·캐시·
해제·streaming 성능은 검증하지 않았다. 원본 405×540 파생 이미지보다 실제
지리 정보가 늘어난 것도 아니다.

## 검증

- `한반도지형타일화면오차SelectorTests`: EditMode 6/6 통과
- `세계지구본Tests`: EditMode 21/21 통과
- 상·하위 상세 단계 동시 활성: 세 비교 모두 없음
- Console: 이번 실행에서 지구본·한반도 지형·SSE 관련 오류 0건
- 기존 Scene의 서버 세션 연결 실패·replay hash 오류는 별도 기존 문제로 남음
- Windows x64 Player build와 평균·p95 프레임 측정은 이번 비교 범위에 포함하지 않음

## 다음 판단

현재 화면에서는 세 결과의 지형 정보 차이가 작다. 4px는 활성 정점과 삼각형을
늘리지만 원본 자료의 정보량을 늘리지 않는다. 기본값을 즉시 4px로 고정하기보다
다음 단계에서 `WorldCRS84Quad` 논리 주소, 실제 source maximum level, 보이는
가지별 선택, 지연 생성·해제와 캐시 예산을 먼저 결속한 뒤 8px를 초기 후보로
다시 계측하는 것이 안전하다.
