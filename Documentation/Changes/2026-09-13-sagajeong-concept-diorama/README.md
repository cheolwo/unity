# 사가정 목표 이미지 기반 모형 표현 · 2026-09-13

사용자 승인: “씬티를 안써도 되니까 목표로 하는 이미지와 최대한 가깝게 표현해줘봐”. 판본 `sagajeong-concept-presentation.r1`. canonical `SimulationWorldShell`의 사가정 관찰 표현만 변경했다.

## 실제 Unity 화면

![전체 1km](whole.png)

![사가정역 주변 확대](station.png)

- Unity 6000.5.6f1 실제 Play Mode에서 `사가정 운영 관찰 카메라`를 이름으로 지정해 1800×1100으로 렌더링했다. 생성 이미지나 합성 후처리 결과가 아니다. OnGUI 패널·실제 마우스 입력 검증은 이번 캡처에 포함하지 않는다.
- [이전 Synty 표현](../2026-09-13-sagajeong-synty-diorama/sagajeong-station-gameview.png)과 비교해 창문, 창틀, 차양, 옥상 가장자리·설비, 도로 가장자리·노면 장식, 가상 녹음과 접지 그림자를 추가했다. 전용 명암 shader와 관찰 카메라 SMAA로 다른 영역의 전역 조명·volume 설정을 바꾸지 않는다.

## 구현 경계

- `사가정모형MeshBuilder`가 건물 고유 ID에 따라 결정적으로 색과 장식을 조립한다. 기본값은 절차적 표현이며 `useSyntyPresentation`을 켜면 기존 Synty 표현을 사용할 수 있다.
- 원자료602개 건물·2,397개 도로 선분, 주소·높이 보완 자료와 canonical Scene 파일은 HEAD 대비 불변이다. 벽 윤곽·최고 높이는 기존 자료를 사용하며 옥상 설비도 그 높이 이내다. 창문 줄은 실제 층수 증명이 아니다.
- 도로 폭·차선·나무는 표현 전용이다. 실제 차로 수나 식재 위치를 확인했다는 뜻이 아니다. 가상 나무는 도로·건물과의 간격을 검사하며 Collider와 업무 상태를 만들지 않는다.
- 목표 이미지와 완전히 같지는 않다. 건물 자료가 비어 있는 구역은 채우지 않았고, 높이 미확인 건물은 기존 임시4m를 유지해 저층이 많다. 실제 외관 재현, 출입구 모델링, 사람·차량·전투 표현은 이번 범위가 아니다.

## 검증

- 최종 컴파일 오류0. 동기식 EditMode의 새 응답에서 총69/69 통과: `사가정`16, `건물높이보완Tests`19, `도로명주소표현Tests`21, `역방어준비Tests`8, `운영관찰WorldTests`5.
- `사가정`16개는 새 모형3, Synty5, 기존 디오라마7, Farm 표시 경계1이다. 원자료 불변·반복 생성 결정성·CW/CCW 외벽 창문·높이 상한·유효 정점/인덱스·Collider0·관찰 layer·렌더러 예산을 검사했다.
- 초기 회귀에서 기존 렌더러 정확히5개 가정이 실패했다. 예산5~40과 재활성화 전후 개수 불변으로 갱신했으며 다른 영역을 숨기는 검사는 유지했다. 최종 실제 렌더러30개.
- 도구의 비동기 시험 상태 파일이 잠겨 과거 결과를 반환하는 문제를 발견했다. 최종 결과는 `run_tests --async_tests false`의 `FilterApplied`와 개별 Results로 확인했다. 이전 기록의 “최종 Synty 필터7/7”은 해당 시험의 새로운 실행 증거로 사용하지 않는다. 이번 Synty5/5가 검증된 최신 결과다.
- 역 주변 화면에서5,769프레임 측정: 평균212.20fps, 프레임 시간95백분위6.38ms. PC Editor·해당 화면 표본이며 모바일/Player 성능 보증이 아니다.
- 실제 Play Mode에서 전체/확대 두 구도를 확인했다. 기존 서버 연결·세션 부재 관련 Console 오류9건이 있어 전체 Scene 무오류·서버 연결·실제 입력 완주·E 승격을 선언하지 않는다.
- 저장 Scene 변경 없이 Play Mode를 종료했고 Editor ready를 확인했다. 운영 서버/DB·다른 영역·기존 `ssalddel.slnx` 변경은 손대지 않았다. 이번 변경은 commit/push하지 않았다.

## 변경 파일

`사가정운영디오라마View.cs`, `사가정지리MeshBuilder.cs`의 지붕 삼각형 재사용 범위, `사가정모형MeshBuilder.cs`, 전용 shader2개, Presentation asmdef의 URP 참조, 새 표현 시험 및 기존 Synty/Farm 표시 시험. 기존 공개 데이터·API·게임 규칙 변경 없음.
