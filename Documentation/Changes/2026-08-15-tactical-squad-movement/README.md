# 서버 결과 기반 전술 분대 이동

## 화면에서 달라진 점

- `SimulationWorldShell`의 농장 구역에 아군 6명과 적군 6명의 Synty 캐릭터 wrapper를 배치했다.
- 서버의 `대형 사수`, `전진 공격`, `전술 후퇴` 결과를 각각 선형·쐐기·종대 대형과 경계·달리기 동작으로 표현한다.
- 분대별 기준점 하나가 전술 전용 NavMesh를 이동하고, 분대원은 결정적 슬롯을 따라가므로 캐릭터끼리 밀려 대형이 무너지지 않는다.
- 현재 팩에 실제 동작 clip이 없어 공용 animation adapter의 절차형 fallback을 사용한다. Synty 원본 prefab과 `.meta` GUID는 수정하지 않았다.

## 자연스러운 표현 리팩터링

- 아군 전방 기준점과 적군 방어선을 분리해 전진 뒤에도 두 분대가 한 덩어리로 섞이지 않는다.
- 아군과 적군이 서로 반대 방향을 보며, 이동 중에는 진행 방향으로 완만하게 회전한다.
- 선형은 폭, 종대는 깊이가 읽히도록 슬롯 비율을 조정하고 분대원은 `SmoothDamp`로 슬롯을 따라간다.
- 같은 구성원에게 새 명령이 적용되어도 절차형 동작 위상을 초기화하지 않는다.
- 행동 자세와 보행 자세 사이의 뼈 회전을 보간해 경계·달리기 전환의 순간적인 튐을 줄였다.

## 지형에 가려진 하체 개선

- 전술용 NavMesh 계산 바닥의 윗면을 실제 농장 지면 높이와 일치시켰다.
- 계산 바닥은 보이지 않는 `BoxCollider`로만 NavMesh에 참여하므로 실제 지형 위에 덧그려지지 않는다.
- 캐릭터 Prefab마다 활성 Renderer의 최저점을 계산하고 발밑에 3cm 여유를 두도록 `VisualRoot` 높이를 자동 보정한다.
- Synty 원본 Prefab은 수정하지 않고 Scene의 wrapper 위치만 보정한다.

## 권위 경계

화면의 이동·대형·경직은 서버가 확정한 상태 사본을 설명하는 표현이다. Unity는 피해, 승패, 이동 완료, `WorldTick` 또는 상태 개정을 만들지 않는다. 캐릭터 prefab을 교체해도 전술 명령과 분대 상태는 바뀌지 않는다.

## 검증

- Unity 공통 표현 mapper 집중 시험: 10/10 통과
- 저장 Scene EditMode 배선·대형 슬롯 시험: 3/3 통과
- Play Mode `대형 사수 → 전진 공격 → 전술 후퇴` 연속 이동: 1/1 통과
- 저장 Scene과 Play Mode에서 전술 바닥 비표시·Collider 유지·캐릭터 최저점이 실제 지면보다 높은지 확인
- Play Mode에서 `WorldTick`·월드 개정 불변 확인
- 대표 Game View: `game-view.png`

공용 플레이어 보행 시험 1건은 기존 곡선 카메라 전환과 즉시 카메라 활성 기대가 충돌해 카메라 assertion에서 실패했다. 전술 분대와 절차형 동작 assertion에 도달하기 전의 별도 기존 기준 불일치다.

![전진 공격 결과를 표현하는 6대6 전술 분대 Game View](game-view.png)

실제 HTTP 전술 adapter, 전술 명령판 uGUI 버튼, 멀티플레이 위치 동기화와 외부 animation pack은 이 변경에 포함하지 않는다.
