# 다중 센터 출고 연습 — 플레이 안내

이 화면에서는 주문을 어느 센터에서 처리할지 비교한 뒤, 선반과 담당 지시에 따라 재고를 예약하고 일부씩 피킹해 포장 준비까지 진행합니다. 실제 주문·재고·직원과 분리된 가상 표본입니다. 이 문서는 조작 방법이며 실제 실행·시험 결과를 기록한 문서는 아닙니다.

## 1. 시작하기

1. Unity에서 열어 둔 Scene의 미저장 변경을 먼저 저장합니다. 미저장 변경이 있으면 출고 플레이 진입을 보류합니다.
2. 상단 메뉴 **Ssalddel → 경영 → 다중 센터 출고 플레이**를 누릅니다.
3. Game View에서 **출고 운영실 / 센터에서 선반까지** 화면을 확인합니다. 왼쪽은 모의 센터와 선반, 오른쪽은 출고 작업대입니다.

메뉴는 기존 공식 Scene인 `SimulationWorldShell`에서 출고 전용 프로필을 실행합니다. 다른 프로필의 진행 내용과 구분된 전용 저장 슬롯을 사용합니다.

## 2. 샘플 주문과 센터 비교

1. **샘플 주문 검토**를 누릅니다. 첫 표본은 같은 상품 3개를 출고하는 주문입니다.
2. **센터 후보 목록**에서 거리·비용과 출고 가능 조건을 함께 읽습니다. 가까운 센터라도 담당자가 없거나 처리 여력이 부족하면 선택할 수 없습니다.
3. **출고 가능한 모의 센터**의 후보와 선반·담당 지시를 확인합니다. 후보를 누르면 해당 센터를 조건으로 출고안을 다시 검토합니다. **전체 센터**는 특정 센터로 제한한 조건을 해제합니다.
4. **출고 예약 확정**을 누릅니다. 주문 검토만으로는 재고를 점유하지 않으며, 예약이 확정된 뒤 예약 수량이 반영됩니다.

**분할 허용**은 여러 센터로 나누는 출고안을 허용하는 조건입니다. 체크했다고 반드시 분할하거나, 전체 거리·비용이 가장 작은 경로를 계산한다는 뜻은 아닙니다. 현재 샘플은 한 센터에서 처리할 수 있습니다.

## 3. 선반 표찰과 부분 피킹

1. **선반 지시 목록**에서 지시를 누릅니다. 선택한 센터와 선반이 노란색으로 강조됩니다.
2. 지시와 선반 표찰을 보며 **위치 코드**, **상품 코드**, **확인 수량**을 확인합니다. 지시를 선택하면 코드와 기본 수량이 입력되므로, 입력값이 현재 지시와 같은지 살펴봅니다.
3. 첫 연습에서는 확인 수량을 `1`로 두고 **입력 수량 피킹**을 누릅니다.
4. 피킹 수량이 1개 늘고 남은 수량이 2개인지 확인합니다. 이어서 확인 수량에 `2`를 입력해 같은 버튼을 누르면 나머지를 피킹합니다.

초기 샘플의 출고 가능 선반 표찰은 `SAMPLE-READY-A-03-2-B`, 상품 코드는 `SAMPLE-WATER-500`입니다. 저장된 진행 상태에 따라 실제 지시와 남은 수량이 달라질 수 있으므로 화면의 현재 지시를 우선합니다. 여러 지시가 있으면 각 지시의 남은 수량을 따로 처리합니다.

표찰 입력은 게임 안의 코드 대조입니다. 카메라로 실제 바코드를 스캔하거나 실제 물건을 집었다는 증거를 수집하는 기능은 아닙니다.

## 4. 포장 준비와 수량 읽기

모든 지시의 남은 수량이 0이 되면 **03 전량 피킹 확인 · 포장 준비**를 누릅니다. 아직 남은 수량이 있으면 이 단계로 진행할 수 없습니다.

처음 실행한 표본에서 한 선반의 수량은 다음과 같이 읽습니다.

| 단계 | 보관 수량 | 예약 수량 | 이번 주문 피킹 수량 |
| --- | ---: | ---: | ---: |
| 예약 전 | 10 | 0 | 0 |
| 3개 예약 후 | 10 | 3 | 0 |
| 1개 부분 피킹 후 | 9 | 2 | 1 |
| 나머지 2개 피킹 후 | 7 | 0 | 3 |

예약은 보관 수량을 곧바로 차감하지 않습니다. 피킹할 때 보관·예약 수량이 함께 줄며, 포장 준비 단계에서 같은 수량을 다시 차감하지 않습니다. **포장 준비**는 실제 포장 완료·기사 인계·배송 완료와 다른 상태입니다.

## 5. 진행 저장과 다시 이어 하기

1. 예약 직후나 부분 피킹 도중에도 **진행 저장**을 누를 수 있습니다. 화면에서 전용 출고 슬롯에 저장됐다는 안내를 확인합니다.
2. Play Mode를 종료합니다.
3. 다시 **Ssalddel → 경영 → 다중 센터 출고 플레이**로 들어갑니다.
4. 같은 로컬 저장 공간에 남아 있는 전용 슬롯 `fulfillment-centers-local-r1`에서 저장된 출고 상태를 불러오는 흐름입니다. 예약·부분 피킹을 저장했다면 새 샘플 주문을 만들기보다 복원된 지시와 남은 수량부터 확인합니다.

버튼을 누른 것과 저장 성공 안내는 구분해야 합니다. 저장하지 않은 변경의 보존을 가정하지 마세요. 다른 시나리오나 출고 모듈이 없는 잘못된 저장 데이터는 새 표본으로 덮어쓰는 대신 실행을 거절합니다.

## 6. 막혔을 때 확인할 것

- **선택 불가 센터**: 후보에 표시된 재고·담당 직원·처리 단위·여력 사유를 확인합니다. 가까운 모의 센터는 직원이 근무 전인 조건이므로, 거리만으로 선택되지 않는 예입니다.
- **위치·상품 코드 불일치**: 선택한 선반 지시를 다시 읽고 입력값을 맞춥니다. 남은 수량보다 많이 입력하지 않습니다.
- **미피킹 예약 취소**: 아직 하나도 피킹하지 않은 주문만 취소할 수 있습니다. 일부라도 피킹한 뒤에는 물건 반납·복구 절차 없이 취소할 수 없습니다.
- **처리를 확인하지 못했다는 안내**: 화면의 최신 상태와 남은 수량을 먼저 확인하고 필요하면 **최신 조회**를 누릅니다. 자동으로 명령을 다시 전송하지 않습니다. 재조회로 미확정 출고안이 해제됐다면 예약 전 **샘플 주문 검토**부터 다시 시작합니다.

연습 화면의 모형과 강조색은 판단을 돕는 표현입니다. 출고 상태는 같은 로컬 시뮬레이션 세션을 다시 조회한 결과를 따릅니다. 이 연습은 실제 운영 서버·운영 DB·고용·정산·현장 스캔이나 물류센터 간 실물 인계를 수행하지 않습니다.
